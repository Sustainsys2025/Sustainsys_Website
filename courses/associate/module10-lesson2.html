Document Loading and Chunking

Master the critical first step of RAG pipelines. Learn how to load documents from various sources, split them into optimal chunks, and prepare them for embedding. Discover chunking strategies that balance context preservation with retrieval efficiency.

  • Master chunk size and overlap parameters
  • Implement document loading for multiple file formats

  • Build a robust document processing pipeline
  • Optimize chunking for your specific use case
Fundamentals

Why Chunking Matters in RAG

Raw documents cannot be directly embedded into vector databases. Every RAG system must split documents into chunks. This process is arguably the most impactful technical decision because it directly determines what information can be retrieved and answered. Poor chunking cascades through your pipeline: bad chunks mean bad retrieval, which means bad LLM answers.

The fundamental problem: Find the right granularity. Too large: irrelevant information included. Too small: insufficient context. The sweet spot depends on your content and questions. A 5000-token policy document might be one chunk or 10 chunks depending on your use case.

Core Insight: Chunking directly limits RAG quality. It's your primary quality lever. Everything downstream depends on getting this right.
Too-Large Chunks
Include irrelevant information. Force LLM to process unnecessary context. Exceed token limits. Low retrieval precision.
Optimal Chunks
Complete information units. Sufficient context. Minimal noise. Precise retrieval. Fit easily within context windows.
Too-Small Chunks
Lack context for understanding. Fragment concepts. Require retrieving many chunks. Increase latency and cost.
Implementation

Loading Documents from Multiple Sources

RAG systems work with documents from many sources: PDFs, text files, web pages, databases, APIs. Each requires different parsing. LangChain provides loaders for common formats, abstracting format-specific extraction complexity while preserving document structure.

Python
# Multi-source document loading
from langchain.document_loaders import (
    TextLoader, PyPDFLoader, CSVLoader,
    WebBaseLoader, DirectoryLoader
)

# Load text file
text_loader = TextLoader("policies.txt")
text_docs = text_loader.load()

# Load PDF
pdf_loader = PyPDFLoader("manual.pdf")
pdf_docs = pdf_loader.load()

# Load CSV
csv_loader = CSVLoader("data.csv")
csv_docs = csv_loader.load()

# Load web
web_loader = WebBaseLoader("https://example.com")
web_docs = web_loader.load()

# Directory batch loading
dir_loader = DirectoryLoader("./docs", glob="**/*.txt")
all_docs = dir_loader.load()

# Combine from all sources
combined = text_docs + pdf_docs + csv_docs
print(f"Loaded {len(combined)} documents")
Strategies

Chunking Strategies: Methods and Trade-offs

Different documents benefit from different chunking strategies. Choose based on your document type, structure, and expected questions.

Fixed-Size Chunking

Simplest approach: split by character count with overlap. Easy to implement but ignores structure. Overlap preserves context at boundaries.

Python
# Fixed-size character splitting
from langchain.text_splitter import CharacterTextSplitter

splitter = CharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200
)
chunks = splitter.split_text(text)

Recursive Character Splitting

Better than fixed-size: splits on natural boundaries (paragraphs, sentences) before resorting to character splitting. Respects document structure and keeps related information together.

Python
# Recursive splitting respects document structure
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    separators=["

", "
", " ", ""],
    chunk_size=1000,
    chunk_overlap=200
)
chunks = splitter.split_documents(documents)

Token-Based Chunking

Most accurate for LLMs: split by token count instead of characters. More precise because tokens directly relate to model limits and costs.

Python
# Token-based splitting more accurate for LLMs
import tiktoken

encoding = tiktoken.get_encoding("cl100k_base")

def split_by_tokens(text, max_tokens=1000):
    tokens = encoding.encode(text)
    chunks = []
    for i in range(0, len(tokens), max_tokens):
        chunk_tokens = tokens[i:i+max_tokens]
        chunk_text = encoding.decode(chunk_tokens)
        chunks.append(chunk_text)
    return chunks
Best Practices

Building a Production Document Pipeline

Here's a complete pipeline with error handling and best practices:

Python
# Production-ready document processor
from langchain.document_loaders import DirectoryLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
import re

class DocumentProcessor:
    def __init__(self, chunk_size=1000, overlap=200):
        self.splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size,
            chunk_overlap=overlap
        )

    def clean_text(self, text):
        # Remove extra whitespace
        text = re.sub(r'\s+', ' ', text)
        # Remove control characters
        text = re.sub(r'[-]', '', text)
        return text.strip()

    def process(self, documents):
        for doc in documents:
            doc.page_content = self.clean_text(doc.page_content)
        return self.splitter.split_documents(documents)

# Usage
processor = DocumentProcessor()
loader = DirectoryLoader("./docs")
docs = loader.load()
chunks = processor.process(docs)
Fine-Tuning

Choosing Optimal Parameters

Chunk Size: 800-1000 tokens typical. Depends on question complexity and document density. Small chunks (500 tokens) for factual Q&A. Large chunks (1500 tokens) for analytical questions.

Chunk Overlap: 10-20% of chunk size typical. 100-200 tokens for 1000-token chunks. Preserves context at boundaries. Too much overlap wastes computation.

Testing: Build test set of questions. Iterate on parameters to optimize retrieval quality. Track metrics like precision and answer quality.

Advanced

Metadata for Chunks and Document Versioning

Add metadata to chunks for filtering, ranking, and tracking document versions. Metadata enables sophisticated retrieval strategies and helps maintain document quality.

Python
# Add metadata to chunks
from langchain.schema import Document
import hashlib

for i, chunk in enumerate(raw_chunks):
    # Create content hash for change detection
    content_hash = hashlib.md5(chunk.encode()).hexdigest()

    doc = Document(
        page_content=chunk,
        metadata={
            "source": "policies.txt",
            "section": "returns",
            "date": "2024-03-15",
            "version": "2.1",
            "chunk_index": i,
            "content_hash": content_hash,
            "importance": "high" if "return" in chunk else "normal"
        }
    )

Metadata strategies: Include source file name to track origin. Add section/topic tags for filtering before retrieval. Include document date and version for freshness checking. Use importance flags to weight retrieval results. Add content hashes to detect when documents change.

Best Practices

Measuring Chunking Quality

Good chunking is invisible—the user never notices it. Bad chunking breaks the RAG pipeline. How do you measure if your chunking is working?

Key Metrics for Chunk Quality

  • Chunk Coherence: Does each chunk represent a complete concept? Measure by checking if sentences are complete and logical units intact.
  • Redundancy: Is essential information repeated across chunks? Some overlap is necessary for context, but excessive duplication wastes tokens.
  • Information Density: Does each chunk contain relevant information? Fillers and boilerplate lower quality.
  • Retrievability: Can the chunk be found by semantically similar queries? Test with sample questions.

Testing Chunking Decisions

Create a small test set of representative questions. For each question, manually identify which documents/sections should be retrieved. Then test your chunking strategy: Does it naturally retrieve those sections? Count successes and failures.

Python
# Evaluate chunking strategy
test_questions = [
    ("How long is the return window?", ["returns_section"]),
    ("What is the shipping cost?", ["shipping_section"]),
]

successes = 0
for question, expected_sections in test_questions:
    retrieved = retriever.get_relevant_documents(question)
    retrieved_sections = [d.metadata["section"] for d in retrieved]

    # Check if at least one expected section was retrieved
    if any(section in retrieved_sections for section in expected_sections):
        successes += 1

print(f"Retrieval success rate: {successes / len(test_questions):.0%}")
Summary

Key Takeaways

  • Chunking is Critical: Limits what RAG can retrieve and answer. Invest time optimizing this step.
  • Strategy Matters: Recursive splitting respects structure. Use for most cases.
  • Token-based Better: More precise than character-based splitting for LLMs.
  • Parameters: 800-1000 token chunks, 10-20% overlap typical. Test and iterate.
  • Clean Data: Remove artifacts before chunking. Preserve semantic structure.
  • Add Metadata: Track source, section, date, version for better retrieval.
